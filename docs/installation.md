# 安装流程

紧接应用的独立“应用库”页签按应用展示可更新、已安装、待安装及下载任务，点击条目后查看各版本与文件并选择具体操作。主列表默认优先进行中的任务与可更新应用，也可按最近修改或名称排序；最近修改取该组最新文件的修改时间。多个安装包或已安装身份不自动代选，下载目录独立设置。系统安装器交接保持待确认，下载、交接及历史版本均不直接代表本机已安装。

第二级安装包页面按每份受管理文件的最后修改时间降序排列，最近修改的在前，Android 原始包和重签包分别参与整体排序。同一修改时间保持原有顺序。恢复记录、刷新、下载完成、导入及重签完成时读取实际文件时间；文件缺失或读取失败时沿用已保存的时间，没有记录时暂按任务创建时间排列。排序时间使用本地文件信息，安装与检查操作本身不改变它。

## Android 安装流程

1. 从目录或详情页下载 Android 应用；需要选择架构时确认后开始，APK 进入应用内下载管理，保留进度、取消和重试。
2. 下载完成后点击“安装应用”。首次使用时，系统可能要求允许华润赢安装应用；返回后继续打开系统安装器。
3. 由用户在系统安装器中确认。只有系统返回成功才标记“已安装”；取消、拒绝权限或失败均保留 APK，可再次点击安装。
4. 安装成功后可打开应用，也可分享 APK。删除下载仅清理文件和记录，不卸载已安装的应用。

APK 保存在应用私有目录，通过不可导出的 FileProvider 临时授予系统读取权限，不申请共享存储权限。仅支持普通单文件 APK，其他格式保留官方入口；系统负责签名、版本和设备兼容性检查，不支持静默安装。客户端进程在系统安装期间终止时，重启后保留 APK 并允许重试。

GitHub APK 资源可开启“下载后重签”，安装确认面板也可开启“安装前重签”，默认关闭。开启后自动选用已有默认密钥；首次确认重签时才生成用户独有的个人密钥，无需先操作创建或选择。取消、关闭开关或切换资源不会生成密钥；确认后复用同一身份。切换、新建、导入和备份集中在“管理密钥”，设置中不常驻密钥入口。首次生成后可立即备份或稍后处理，之后点击“管理密钥”导出。已记住的密钥丢失或损坏时要求导入原备份，不自动生成或换用另一把密钥。备份是包含私钥与证书的标准 `.p12` 文件，使用用户设置的至少 8 字符密码加密，通过 Android 系统文件选择器保存至自选目录或网盘；密码不会保存。密钥管理显示导出时间，导出记录不保证文件仍存在或可恢复。

默认个人密钥流程已通过静态分析、116 项相关 Flutter 测试、Android ARM64 Debug 与原生测试包构建，以及 API 33 模拟器上 15 项原生测试。覆盖确认前不创建、首次备份提示、默认复用与切换、密钥丢失／损坏后的恢复、并发首次请求仅生成一把密钥，以及旧任务重签完成不覆盖后来确认的默认身份；未在真机上手动验收本轮流程。

重签副本与原 APK 位于同一任务目录，文件名在原名去掉扩展名后添加 `-huarun-sign.apk`，例如 `FlClash-0.9.1-android-arm64-v8a-huarun-sign.apk`，原包保持不变。已有 `resigned/` 子目录中的副本继续用于检查、安装和分享；重新重签时改用新文件名。

Android 下载管理将每份 APK 显示为独立内容，按下载或导入时的原始身份区分：

| 标识 | 包名 | 签名 |
| --- | --- | --- |
| 原始包 | 原包名 | 原签名 |
| 重签包 | 包名不变 | 个人签名 |
| 改包重签 | 修改包名 | 个人签名 |

改包后再次只重签仍标为“改包重签”；修改回最初包名后标为“重签包”。“原始包”指本次下载或导入时的文件，不根据证书推测其是否为官方版。每条展示自己的文件名、APK 实际包名、版本、文件大小与签名证书 SHA-256；证书默认显示缩略摘要，可展开完整内容。包信息在后台按需读取并在当前页面复用，刷新会重新读取；读取失败可单独重试，不将所选密钥、Release 标签或文件名推测为实际 APK 信息，也不把展示检查用作安装授权。

每条分别提供安装、分享、删除和“修改包名／重新签名”。三类包都可作为输入，选择个人密钥后仅重签，或开启“修改包名”后重签；确认才生成独立副本，取消不创建密钥或文件，生成后不自动安装。安装方式面板也显示三类标识，华润赢安装均可主动选择安装前重签。只有主动点击原始包条目才会安装或分享原包；重签失败、取消或副本丢失时不会自动回退原包。安装前独立读取并核对所选文件的摘要与实际签名，系统安装器和其他安装器也接收同一份已确认文件。独立生成副本不触发覆盖安装，安装时仍按最终文件执行降级与兼容性检查。

已有副本或安装记录时，再次处理会在独立目录创建新条目，保留所选源包、先前副本及安装结果。派生任务保存最初包名、来源任务、本次密钥和独立输入快照，快照不重复显示为原始包；即使来源条目已删除，仍可安装、分享、再次处理或重试生成副本。删除派生条目会清理该条目的输出、私有输入快照与临时文件，其他条目不受影响。分类、源身份与密钥随记录保存，刷新和重启继续沿用，各条目按各自输出文件修改时间排序。

删除确认仅显示当前点击的包，左侧按钮为“取消”，不再合并勾选两份文件。确认只删除该文件与其临时文件，另一份及下载记录继续保留，全部包移除后才清理记录。仅保留重签包仍可继续检查、分享和安装；仅保留原始包可沿原身份重新重签，也可明确选择安装或分享原包。删除结果和安装结果所属文件会保存，重启后不会把已删除条目重新列出；兼容旧记录与 `resigned/` 路径，不卸载已安装应用。

文件名调整已通过静态分析、125 项下载及 Android 相关 Flutter 测试、Android ARM64 Debug 与原生测试包构建；API 33 模拟器上 5 项原生重签测试通过，使用自制 APK 验证同目录副本、原包保留和 v1／v2／v3 签名。旧目录恢复、交接、删除和重新重签后的重启恢复由 Flutter 测试覆盖；本次未更新真机应用或改动其现有 APK。

密钥选择与备份表单采用中性分组和右侧勾选，证书摘要点击展开，两个密码字段可分别显示或隐藏。重签选项随资源滚动，取消与下载按钮固定在底部。密钥表单通过取消、确认或空闲时的系统返回关闭，处理过程中禁用退出及重复操作；系统文件选择结束后清空密码。窄屏表单支持内容滚动、键盘避让与大字体，浅色和深色使用对应的填充层级。

### 修改包名并重签

下载版本／资源选择和安装前的重签选项下可开启“修改包名”，默认关闭。新包名须与源 APK 不同，至少包含两段，每段以英文字母开头，其余使用字母、数字或下划线；受资源表固定字段限制，最长 127 个 ASCII 字符。安装前建议原包名加 `.huarun`，下载时尚未读取 APK 则填写自选包名。输入无效时不能确认，也不会因此生成密钥。关闭开关、取消、切换版本或资源不执行修改。

确认后保留所选文件，生成 `原文件名-huarun-sign.apk`，标识为“改包重签”独立展示和操作；已有副本时使用新的任务目录，连续处理不会覆盖先前文件。记录保存最初包名、本次源包名、新包名、所用密钥与副本摘要，重启及重试沿用同一设置。同一资源选择不同新包名会生成不同任务；后续选择版本可带出已有改包记录的包名与密钥，包括改包后再次仅重签时使用的新密钥，仍需用户主动开启选项并确认。原密钥缺失或证书不匹配时要求导入备份，不自动切换另一把密钥。

原生实现在 `ApkPackageEditor.kt`，直接依赖 Maven Central 的 `io.github.reandroid:ARSCLib:1.4.0`：

- 参考 [APKEditor](https://github.com/REAndroid/APKEditor) 使用 ARSCLib 编辑二进制资源的方式，以及 [ARSCLib 的 ApkModule](https://github.com/REAndroid/ARSCLib/blob/main/src/main/java/com/reandroid/apk/ApkModule.java) 和 [AndroidManifestBlock](https://github.com/REAndroid/ARSCLib/blob/main/src/main/java/com/reandroid/arsc/chunk/xml/AndroidManifestBlock.java)。
- [Apktool](https://github.com/iBotPeaches/Apktool) 用于参考解包、资源重建思路，运行时不嵌入其桌面命令行或 aapt/aapt2。[AppManager](https://github.com/MuntashirAkon/AppManager) 仍作为签名与密钥管理设计参考。
- 先保留组件的原始完整类名，覆盖相对名称、无包前缀的短名称、Application、Activity／alias、Service、Receiver、Provider、备份代理及组件工厂，再修改应用 ID 和资源表包名；不改 DEX 类名或资源 ID。
- 为本 APK 声明的 Provider authorities、自定义权限及其 Manifest 引用生成新标识；隔离显式全局进程名和 task affinity，保留外部权限、查询包名与其他应用接口。
- 重建保留原压缩方式，未压缩原生库按 16 KB 对齐，再复用现有 apksig 签名、证书和摘要检查。实际输出包名与版本必须符合本次选择，安装前继续独立检查副本，降级仍按实际待安装包名和版本码判断。

仅支持普通单文件 APK；拆分 APK、共享 UID、插桩包、overlay、静态共享库及 SDK 库明确拒绝。身份或组件字段通过不支持的资源引用声明时停止处理。失败、取消及中断保留原包，不自动安装原包；重建使用的 `.unsigned` 文件属于该重签包的临时文件，重试与删除一并清理。

改包后的应用有独立身份和数据，后续覆盖更新需沿用相同包名及密钥。代码、原生库或服务端对原包名／官方证书的依赖不进行通用修补；可能影响启动、登录、推送、深链接与跨应用通信。生成和签名验证成功仅证明安装包已按选择处理，不等于所有功能均可正常运行。

换机、重装华润赢或清除其数据后，可导入 `.p12` 及密码恢复相同签名身份，继续更新之前的重签版；单独保存 APK 或证书不能恢复私钥。导入仅支持包含一把 2048 至 8192 位 RSA 签名私钥及匹配证书的 PKCS#12 文件，重复导入不增加另一把身份。新私钥在本机使用 Android Keystore 的 AES-GCM 密钥加密保存，不参与系统自动备份。旧版生成的 Android Keystore 密钥继续可用，但仅限本机且不可补导出，丢失后不能用新密钥覆盖更新旧重签版。关闭重签不删除密钥，重签仍须经过系统安装确认。

## Windows 系统交接

下载管理的“使用系统安装器”将 EXE／MSIX 交给系统打开，MSI 使用系统目录中的 `msiexec /i`，ZIP 交给压缩包查看工具。“查看文件”在资源管理器中选中安装包。系统窗口打开后仍只记录“已交给系统／安装结果尚未确认”，不据此推断已安装；系统的授权和安装确认由用户处理。

打包桌面环境可能将 AppData 中的文件重定向到私有缓存，外部系统进程无法使用应用看到的逻辑路径。Windows 原生层在交接和定位前，通过已打开的普通文件句柄解析实际本地路径；下载记录保留原路径。相对路径、UNC、设备路径、目录及末级重解析点仍不接受，不拼接 shell 命令，也不改变系统权限设置。

## Mac 安装流程

1. 下载写入 `.part`，完成且长度验证通过后保存为安装包；单文件上限 4 GB，最多 3 个并发下载。公开 HTML 有与该文件明确对应的 SHA-256 时，在后台 isolate 校验，不一致则丢弃文件；自动或手动安装前再次校验。GitHub 校验值只从真实 Release 附件行读取，网站普通链接可提供 `data-sha256`；缺失时明确显示未取得校验值，不声称已验证，也不调用 GitHub JSON API。
2. 用户点击安装并确认；本次安装应用的 `com.apple.quarantine` 默认由安装助手处理，无需额外选择，旧版隔离处理偏好不再生效。
3. Swift 助手以普通权限挂载只读 DMG 或解压 ZIP，在私有临时目录准备应用，检查应用标识、可执行文件、实际架构及符号链接。展开及复制前检查磁盘空间，显示挂载、解压、验证、复制与替换等阶段；系统工具有超时和有界诊断输出，两个输出管道持续读取，避免卡死。
4. 优先以普通权限复制到 `/Applications` 的私有暂存目录，再次验证并处理隔离属性。首次安装原子移动到最终路径；已有同名、相同应用标识的应用使用原子交换替换，失败保留旧版。不同标识、文件或符号链接不覆盖；不删除应用外的设置与数据目录。目标应用正在运行时询问“是否退出当前应用，继续安装？”，确认后以普通权限请求该应用正常退出，等待退出并重新验证后继续安装；取消不退出，拒绝退出或超时则提示手动处理，不强制终止。退出确认绑定目标路径与应用标识，目标变化时重新询问。
5. 显示安装包的签名校验、Team ID、系统评估与公证信息；未签名或本地签名应用仍可安装，公证只有明确的系统结果才标记通过。替换已有有效 Team ID 的应用时，开发者身份变化须单独确认；确认绑定目标路径、应用标识及前后身份，复制后和替换前重新检查。
6. 普通权限无法写入时，询问是否继续系统管理员授权。后台队列通过 `/usr/bin/osascript` 的 `with administrator privileges` 执行内置固定助手的受限 `commit` 操作，不阻塞 Flutter 主线程。每次操作独立授权，不保存密码，没有常驻 root 服务；授权命令返回前显示“等待系统授权并完成安装”，不伪造连续复制进度，也不强制中断可能正在替换应用的提权助手。
7. 安装成功后由用户点击打开应用，安装过程不会执行安装包中的程序。客户端在安装中退出时，重启保留仍在的安装包，并提示结果尚未确认、可重试安装，不自动标记成功。
8. DMG／ZIP 可选择“手动安装”，PKG 使用系统安装器；系统成功打开文件只记录“已交给系统”，不等同安装完成。取消或失败保留文件；再次刷新和重启也不推断系统安装结果。

网页内容不会作为 shell 命令执行；主程序与解压过程始终保持普通权限。第一版尚未实现 SMAppService／XPC 常驻助手；需要长期授权或后台更新时，再单独设计签名身份、调用者校验和服务生命周期。

限制：DMG／ZIP 必须包含一个可识别的应用；Apple Silicon 上拒绝 Intel-only 包，不自动安装 Rosetta；不做跨应用标识迁移、重新签名或复杂安装脚本。移除隔离属性不等于签名或公证。客户端不全局关闭 Gatekeeper；macOS 沙盒已关闭，用于独立分发安装助手。
