# 内容来源与静态镜像

## 设置与行为

高级设置入口位于设置首页底部，首页不展示网络分组、具体来源与线路。来源默认为自动，已有手动选择继续保留。

设置 → 高级设置 → 内容来源提供五个选项，统一选择后直接生效：

| 选择 | 行为 |
| --- | --- |
| 自动（默认） | 首次依次尝试华润赢网站、GitHub Raw 直连、GH-Proxy、jsDelivr；连接失败、超时、HTTP 429 或 5xx 时尝试下一来源。回退成功后优先使用该来源 2 小时，期间其余来源沿上述顺序各尝试一次。到期后的下一次联网加载或用户手动刷新重新从网站开始，并在设置中显示最近成功来源。 |
| 华润赢网站 | 固定从 `https://huarun.win/` 获取内容，不自动转向镜像。 |
| GitHub 镜像 | 固定直连公开仓库的 Raw 内容和图片，不自动转向代理或其他镜像。 |
| GH-Proxy | 固定通过 `gh-proxy.com` 读取同一 GitHub 镜像的内容和图片，不自动转向直连或其他镜像。 |
| jsDelivr 镜像 | 固定通过 `cdn.jsdelivr.net` 获取同一公开仓库的内容，不自动切换。 |

设置只保留这一份来源选择，移除独立的“GitHub 加速”入口及选项分组。“当前来源”直接显示所选名称；自动模式在 GitHub 镜像通过代理成功时显示“GH-Proxy”。选择 GitHub 镜像或 GH-Proxy 同时决定后续公开 GitHub 更新信息与应用内文件下载的直连或代理方式；选择自动、网站或 jsDelivr 时，这些 GitHub 请求自动在直连和代理之间回退。

目录、详情及分页 HTML 的每个来源请求最多等待 5 秒，覆盖请求准备、连接、重定向和响应接收；连接与发送阶段各设 3 秒超时。自动模式下发生可切换的错误或达到总时限后，取消当前请求并立即尝试下一来源，不增加等待或重复重试；网站、GitHub 镜像（含直连与代理）及 jsDelivr 都无响应时，网络等待合计约 15 秒，随后显示已有缓存或错误。该时限不包含缓存读取及后续 HTML 解析，也不适用于图片、GitHub Release 版本选择或安装包下载。固定来源同样使用每次 5 秒上限，但不会自动切换。

2 小时从一次回退成功解析时起算，期间继续成功读取同一来源不会延长保持时间；来源及起算时间一起保存在本机，重启后沿用剩余时间。到期不启动后台探测、不丢弃仍有效的内容缓存，下一次实际需要联网获取 HTML 时再按“网站 → GitHub Raw 直连 → GH-Proxy → jsDelivr”尝试。网站恢复则继续优先网站，仍需回退则重新开始 2 小时；保持期内当前来源失败仍可立即切换。旧记录缺少起算时间、时间无效或系统时钟回拨时，下次联网从网站开始。

用户主动刷新应用目录、详情、公开栏目或应用库时，即使仍在保持期也立即从网站重试；同一次应用库刷新中的版本详情检查复用已经得到的来源结果，不对每份详情重复重置保持期。固定来源不受这一重试策略影响。显式切换来源会清除保持期，切回自动后从网站开始。缓存读取、站内图片加载和正常浏览不会主动重置保持期；请求保存来源选择代次，手动刷新或恢复尝试前的迟到结果不能改回旧优先来源或重新延长保持期。

选择保存在本机。切换后重新加载目录、详情及站内图片，保留导航、搜索、筛选与下载任务。隐藏栏目的旧结果失效，重新进入时按新来源获取。固定来源暂时不可用时，保留该来源可用的缓存并提示重试；没有缓存时显示错误。自动模式将 TLS 握手期间对端断开连接（Dart 的 `Connection terminated during handshake`，无底层 TLS 错误码）视为连接失败并尝试另一来源；404、页面结构异常、证书校验失败及其他 TLS 错误仍不切源，以免把镜像缺页或不可识别的响应掩盖成成功。

GitHub 与 jsDelivr 镜像读取同一份网站公开静态产物，内容可能晚于网站。网站现有发布流程在上传及数据库确认后同步 GitHub 镜像；jsDelivr 对 `main` 分支有独立 CDN 缓存，内容更新可能晚于 Raw，客户端刷新不会清除 CDN 缓存。选择镜像不会使购买、账号、纠错、第三方下载等在线服务转由镜像提供，也不保证任何网络环境下都可访问。

## GitHub 加速

GitHub 传输方式由单一内容来源决定，不再单独保存用户选择：GitHub 镜像对应直连，GH-Proxy 对应代理，其他选择对应自动回退。处理客户端发出的公开 Raw 文本请求、GitHub 内容镜像的站内图片，以及应用内管理的 GitHub Release 附件、源码压缩包和 Raw 文件下载；代理入口为 `https://gh-proxy.com/`，在真实 GitHub 地址前添加该前缀。不修改模型、Hub 或下载记录中的原始地址、版本及公开摘要，不生成不存在的附件链接。

内容来源为自动且无保持期时，HTML 按“网站 → GitHub Raw 直连 → GH-Proxy 转发 Raw → jsDelivr”依次尝试。固定 GitHub 镜像或 GH-Proxy 时只尝试所选方式。新选择保存为 `contentSourceMode`；旧版来源为自动或 GitHub 镜像且固定使用代理时，兼容恢复为 GH-Proxy；旧版网站和 jsDelivr 选择继续保留，其他组合按原来源恢复。已有新选择时，旧的 `contentSource` 和加速偏好均不能覆盖它。

自动模式先直连，连接失败、超时、HTTP 403／408／429／5xx 或代理返回非预期的传输响应时尝试另一条线路。404、内容解析失败和证书校验失败不以加速掩盖。Raw 文本读取与安装包／资源下载分别保存最近成功线路和 2 小时回退起算时间；重启沿用剩余时间，普通成功不续期。到期后下一次联网重试直连，没有后台探测；保持期内代理失败可立即回到直连。固定连接方式不自动换线路。

手动刷新目录、详情、栏目或应用库同时清除加速的保持期；手动检查客户端更新及刷新日志只重试 Raw 直连，手动重试下载只重试下载直连。刷新“内容来源”页只重新读取偏好，不主动清除保持期。显式切换来源清除旧状态、取消旧内容请求并重新加载内容和图片，后续请求使用新选择；进行中的下载沿用开始时的设置，其迟到结果不覆盖新偏好。

目录镜像仍受每个内容来源 5 秒总时限约束。自动加速在该预算内为直连和代理各分配至多 2.5 秒，固定线路保留 5 秒；连接／发送阶段不超过 3 秒。客户端更新信息读取的两条线路共用 20 秒网络预算。下载仍沿用原连接和接收超时，暂时性错误最多进行三次下载尝试，自动换线路计入该上限，不为每条线路重新增加三次重试；取消同时终止回退。

续传记录另存实际传输地址。没有已知 SHA-256 时，切换直连与代理会丢弃旧半成品并重新下载；有相同预期摘要时可继续按原有 Range、长度和 HTTP 校验信息核对续传，最终仍核对完整文件摘要。下载成功线路在已有的摘要校验通过后记录；完整半成品直接复用而未联网时不重新起算保持期。安装身份、签名及平台兼容性检查继续执行。

GitHub 镜像图片优先跟随最近成功的 Raw 线路，直至新的文本请求确认线路；图片缓存命中、成功或失败均不设置、清除或延长任何全局保持期。自动加速允许单张图片在直连与 GH-Proxy 之间回退，固定加速方式只用所选线路；两条线路均失败后，内容来源为自动时再尝试其他内容来源。图片继续沿用现有加载时限，按实际传输 URL 分开缓存。切换设置后的旧图片结果不覆盖新线路的显示。

**网站已收录的版本与附件优先从详情 HTML 读取，随后按当前来源策略下载真实 GitHub 文件。** 默认最近 5 个发布及当前推荐版本的资料由网站采集并随静态页面发布；选择 GH-Proxy 时安装包直接使用代理，缺少公开摘要不触发额外的 GitHub 页面请求。

缺少隐藏版本资料或用户主动载入更多版本时，GitHub 版本列表、版本详情和附件 HTML 仍直连 GitHub。2026-10-23 对公开仓库的实际请求中，GH-Proxy 的 `/releases` 返回自有脚本页面，`/releases/tag/...` 与 `expanded_assets` 返回 HTTP 403，不能交给现有 HTML 解析器。客户端不引入 GitHub JSON API、不执行代理网页脚本。官网、jsDelivr 与外部图片、外部网页、商店及交给浏览器的下载不经过该代理。

实现位于 `lib/services/github_acceleration.dart`、`lib/services/resumable_download.dart`、`lib/services/app_updates.dart`、`lib/data/repository.dart` 与 `lib/ui/settings.dart`。服务为第三方公共代理，可用性随网络和服务状态变化；一次成功请求不代表 Android 网络或所有附件均已验证。

## 地址与缓存

镜像仓库：[huarunwin/huarunwin-static](https://github.com/huarunwin/huarunwin-static)。未启用 GitHub Pages，客户端通过 HTTP 获取 HTML 原文并使用现有 DOM 解析器，不执行 JavaScript、不新增内容 API 或独立内容 JSON。

| 网站地址 | GitHub Raw 请求 | jsDelivr 请求 |
| --- | --- | --- |
| `https://huarun.win/` | `https://raw.githubusercontent.com/huarunwin/huarunwin-static/main/index.html` | `https://cdn.jsdelivr.net/gh/huarunwin/huarunwin-static@main/index.html` |
| `https://huarun.win/apps/flclash` | `https://raw.githubusercontent.com/huarunwin/huarunwin-static/main/apps/flclash.html` | `https://cdn.jsdelivr.net/gh/huarunwin/huarunwin-static@main/apps/flclash.html` |
| `https://huarun.win/jichang` | `https://raw.githubusercontent.com/huarunwin/huarunwin-static/main/jichang.html` | `https://cdn.jsdelivr.net/gh/huarunwin/huarunwin-static@main/jichang.html` |

站内图片在各镜像根地址后保留原路径，逐段编码中文与空格。两个镜像的 HTML 响应均允许 `text/html` 或 `text/plain`，响应地址须与所请求的镜像地址一致；模型与 DOM 解析器不因传输来源改变。

内容模型与解析基准始终使用原网站 URL，保留站内链接、查询参数、锚点及原始下载／购买地址。镜像只改变公开 HTML 和站内图片的传输地址，不把 Raw 或 jsDelivr 地址用于分享、购买、下载、纠错或外部网页访问。外部图片不改写。站内图片优先跟随当前成功来源，自动模式的单张图片加载失败后按网站、GitHub Raw、jsDelivr 的顺序尝试剩余来源；其中 GitHub Raw 按统一来源选择尝试允许的线路，每个传输地址最多尝试一次，不修改全局来源偏好或保持时间。

网站缓存沿用原路径，GitHub Raw 与 jsDelivr 的 HTML 缓存分别位于内容目录的 `github/` 和 `jsdelivr/` 子目录；内存缓存也包含来源标识，GH-Proxy 与直连 GitHub 共用同一份 Raw 内容缓存，旧网站与 GitHub 缓存保持兼容。图片按实际请求 URL 缓存。显式切换递增修订号并取消旧请求，异步解析与界面加载检查修订号／代次，旧请求不能回写当前页面。客户端缓存有效期仍为 30 分钟；刷新失败时提示正在展示上次保存的内容。

实现主要位于 `lib/services/content_sources.dart`、`lib/data/repository.dart`、`lib/services/app_controller.dart`、`lib/ui/content_image.dart` 和 `lib/ui/settings.dart`。客户端自身版本更新的数据仍来自 `huarunwin-hub`，传输方式遵循上述统一选择。
