# 数据与结构

网站 HTML 与 GitHub 发布页请求共用 `lib/services/html_client.dart`，User-Agent 使用 `HuarunWin/<当前应用版本> (+https://huarun.win)`。版本优先读取构建时注入的完整 `HUARUNWIN_VERSION`，未注入时从已安装应用的包信息读取，不随版本发布手动维护；包信息不可用时仅保留应用名称与网站标识，避免影响内容加载。

内容获取只请求公开 HTML，不要求 JSON API、独立 JSON 文件或执行网页 JavaScript。已有 JSON-LD 可补充版本和日期。本地缓存与任务索引使用 JSON 编码，与网站接口无关。客户端自身更新按用户要求读取公开仓库 `huarunwin-hub` 的 `api/updates.json`，区分正式／测试渠道，使用各版本配置的下载地址，不参与网站目录取数，规则见 [发布与许可](releasing.md)。纠错及 Android 的机场／VPS 购买、访问网站入口使用 WebView 加载网页并执行交互所需的 JavaScript，不参与目录内容获取与解析。服务目录与详情继续使用原生 HTML 解析和页面；站内跳转及安装包下载按原有流程处理，其余购买／访问链接在 Android 的 WebView 中打开。

应用内核筛选按需读取并缓存网站现有的 `/core/{slug}` 分类 HTML，以正确包含多内核应用。价格区分完整功能免费、付费和费用待核实；“免费下载”不等于完整功能免费，缺少价格信息的历史条目不猜测归类。代码状态保留许可限制说明。

综合排序保留网页目录顺序，并将已下架条目放在末尾。开源热度默认按卡片公开的近 7 日新增 Star 数排序，可选择今日／7 日／30 日与新增数／新增比例；评分数按公开的商店评分数排序，均只纳入有精确数据的条目，已知的零值有效。统计的原始来源与观察时间保留在悬停说明中；网站没有在默认 HTML 中展示的商店统计不从内部数据补取。

最近更新仅在选择该排序后，才为当前筛选结果读取详情 HTML／JSON-LD 的版本或配置更新日期，最多同时请求 4 页，复用详情缓存。加载时仅显示 loading 动画，不展示读取数量、进度条、排序说明或停止按钮；失败可重试，切换筛选或离开目录停止继续派发请求，已经发出的请求可完成缓存。未取得与网站未记录的日期分别标记并置后，不以网页缓存时间代替版本日期。

600 dp 以上的平台与设备收进“平台”下拉菜单，放在内核左侧，与代码状态和价格同排。桌面有侧栏时在侧栏选择应用类型，主区域保留四个筛选菜单与重置入口；没有侧栏的桌面窗口提供五个菜单。平台选中“全部”时入口显示“平台”，具体平台或设备直接显示当前值（macOS 显示“Mac”），当前设备平台排在“全部”之后。长标签可省略并通过提示查看全文，大字体下可换行。排序置左，结果数量与网格／列表切换置右。

宽度小于 600 dp 时，各平台均采用 Android 的单列目录：搜索框独立一行，下方以五个等宽胶囊按钮提供应用类型、平台、内核、代码及价格筛选，不再共用外层卡片。下一行显示排序、热度周期与排序依据菜单；长标签或大字号空间不足时横向滚动。数量在空间足够时置于排序右端，否则独立右对齐；不显示重置筛选入口、视图切换或“已缓存”，不保留额外工具栏占位。窄屏应用卡片移除“支持平台／运行环境”和“费用”内层信息区及其间距，下架状态保留在副标题中。

所有页面在各平台、各窗口宽度统一移除页面主标题、搜索、筛选和排序区下方的固定说明文案及对应留白；目录底部与筛选面板也不重复显示搜索范围、网页载入范围、价格比较规则或排序解释。标题区仅保留主标题、返回和操作入口，范围通过搜索框提示与结果数量体现；正文、条目实际信息、加载或错误反馈及操作确认继续保留。

开源热度只使用公开 HTML 中的精确统计：周期可由 `data-stars-today`、`data-stars-7d`、`data-stars-30d` 读取，旧版 7 日文本继续兼容；新增比例按所选周期新增数除以总 Star 排序，不使用显示时的一位小数，真实零保留，缺失值不推算。今日指最新采集对应的 GitHub 日期。当前已发布 HTML 仅有精确的 7 日新增数和总 Star，可用 7 日新增数／新增比例；今日与 30 日完整支持需要网站补充上述 HTML 标记，缺失时显示无数据并保留切回综合入口。

各平台窄屏应用首页的类型、平台、内核、代码、价格、排序及热度入口统一使用就近展开的圆角浮动菜单，当前选项右侧显示品牌色勾选，点击后立即应用并关闭。筛选入口选中后只显示当前值，例如“Mihomo”“开源”“免费”，选择“全部”时恢复类别名称；五个筛选入口等宽排列，长标签或大字号时统一增宽并支持横向滚动。长列表可在菜单内滚动，重新打开自动展示当前选项；点击外部或按返回键关闭不修改条件。排序显示当前值，热度周期和排序依据继续在右侧展示。

其他目录的筛选和下载、安装等确认流程继续使用自适应面板：窄屏从底部展开，取消和确认固定在底部，避让键盘；选项切换只改草稿，确认后才应用。

内容缓存及下载历史保存在本机应用支持目录；macOS 为 `~/Library/Application Support/win.huarun.huarunwin/`。下载历史仍固定为该目录下的 `downloads/tasks.json`，不随安装包保存目录切换，继续兼容旧列表格式。偏好由 SharedPreferences 持久化。详情按需加载，默认缓存有效期 30 分钟。

网站、GitHub Raw 与 jsDelivr 镜像共用 HTML 解析器，`lib/services/content_sources.dart` 只选择传输地址；两个镜像读取同一公开仓库，模型、相对链接解析、分享和下载仍使用原网站地址。`CatalogRepository` 按来源隔离内存与磁盘缓存，原网站保留旧缓存路径，镜像分别使用 `github/` 和 `jsdelivr/` 子目录。自动模式按网站、GitHub Raw、jsDelivr 顺延，回退成功后优先该来源 2 小时，期间普通成功请求不续期；最近来源与保持期起点在同一偏好记录中串行保存。到期后的实际 HTML 网络请求或用户手动刷新重新从网站尝试，原有缓存保留；旧记录没有起点时同样从网站开始。仅在连接错误、超时、HTTP 429 或 5xx 时切换；404、解析异常和证书错误不触发内容切换。显式选择递增来源修订号、取消旧请求，并通过修订号及页面加载代次防止迟到结果覆盖新内容；恢复尝试及手动刷新另有来源选择代次，旧请求不能改回旧来源或延长保持期。`lib/ui/content_image.dart` 为站内图片选择对应地址，图片跟随当前成功来源，自动模式的单张图片失败按网站、GitHub Raw、jsDelivr 的顺序尝试其余来源，每个地址最多一次，不据图片失败改变全局内容来源或保持时间。详细路径、设置及镜像维护见 [内容来源与静态镜像](content-sources.md)。

下载历史逐条解码，损坏记录、重复标识或无效受管理路径不阻断后续有效记录；文件检查发生暂时性 I/O 错误时保留该条记录。发现损坏时，先将原文件完整字节写入独立的 `downloads/history-recovery/recovery-*/tasks.json`，成功后才原子替换主历史；每次恢复使用新目录，不覆盖先前备份。备份失败或原文件暂时不可读时暂停历史写入，刷新后重试；读取恢复会合并期间新增任务，不重复载入已有任务。应用库及文件列表展示恢复或保存异常。备份含原始历史中的路径与记录，不自动上传，分享诊断资料前须脱敏。

应用库由现有下载条目和本机查询结果组合生成，新增可选身份字段并兼容旧下载历史。主导航在应用之后提供独立入口，进行中的任务数同步显示；设置仅保留下载目录。应用库与各目录共用稳定的页面树，首次进入才创建，切换页签或窗口布局保留搜索、筛选、排序和滚动位置，重新激活页签时刷新本机与文件状态。离开页签后不继续派发版本详情检查；下载事件通过根导航选择已有应用库并清空旧搜索、回到列表顶部，详情及栏目不另建一份应用库路由。应用按类型与 ID 关联，旧网络下载记录仅在客户端精确名称唯一时关联；导入包及无法关联的资源继续可见，派生 APK 的私有输入快照不重复列出。本机可启动应用共用一次原生查询快照，已知 APK 包名另逐个核对后在本轮检查中复用；只有确认存在的本机应用才读取详情 HTML 比较版本，最多同时进行 4 份检查。文件状态变化时重新检查，下载字节进度只刷新显示；新的刷新、操作或退出页面使旧检查停止继续派发，并防止旧结果覆盖新状态。点击应用统一进入应用管理页：`DownloadsPage` 在同一滚动区加入 `AppLibraryOverview`，只展示所选应用的文件及新生成的派生条目，具体安装、重签、分享和删除流程沿用原实现。

管理页复用应用库持有的本机与版本状态，进入时刷新本机和文件，手动刷新同时更新公开内容；没有文件时显示本地安装包为空，仍可根据已确认状态打开或更新应用。“查看应用介绍”单独进入网站内容的原生详情。Android 管理页在本次停留期间保留已知包名，交由原有本机查询核对，删除下载记录后仍能展示该身份；多个已安装身份分别显示，不合并打开或更新目标。概览中的安装操作直接复用当前文件页的安装入口，开始新下载仍返回同一个应用库页签。

Android 卸载入口绑定概览中点选的 `AppDownloadStatus.installedPackage`，单身份放在次要操作区，多身份逐个展示；用户确认前不调用原生通道。`NativeInstaller.uninstallAndroidApp` 经现有 installer 通道交给 `ApkInstaller`，再次检查所选包名确实已安装，只显式启动系统候选的 `ACTION_UNINSTALL_PACKAGE` 界面，使用普通 `REQUEST_DELETE_PACKAGES` 请求权限，不申请全量包查询或静默删除权限。安装与卸载交接互斥，返回只表示系统界面已关闭；Flutter 等待已有刷新结束后再共用本机／文件刷新核对，取消及失败不直接改写安装事实或删除文件和记录。进程中断后继续按重新激活时的查询结果显示。

桌面卸载通过 `NativeInstaller.uninstallApplication` 及同一管理页确认流程处理。`AppDownloadStatus` 区分已确认安装与是否可打开，新增内存中的 Bundle ID／`uninstallId`，多个真实安装记录保存在 `LibraryAppStatus.installations`，不从下载文件名生成卸载命令。macOS 确认前读取新快照，原生交接前再次检查顶层应用目录、非符号链接、Bundle ID 与版本，拒绝系统／自身及运行中的应用；已有授权时直接复用常驻助手，未授权时先由 `NSWorkspace.recycle` 执行普通权限废纸篓操作。只有需要首次授权或修复尚未派发变更的助手连接时，才返回绑定路径、应用身份、版本和设备／inode 的 `permission_required`；Flutter 在当前操作中单独确认后，通过系统授权安装或修复受限助手并调用 `trash`，此后跨操作与重启复用，不提供独立管理页。助手校验发起客户端与用户，授权后复核应用及运行状态，通过目录句柄向经验证且归属原用户的同卷废纸篓执行排他移动，遇到重名使用唯一名称；不复制后删除、不改变权限、不永久删除，不使用 root 废纸篓。取消保留重试，其他失败定位 Finder。Windows 读取 HKCU／HKLM 卸载注册项的 32／64 位视图，按真实显示名称与目录名称／别名精确匹配，交接前重读所选注册身份、名称与版本；MSI 使用系统 `msiexec /x`，普通卸载只使用已登记的本地 EXE，不使用 QuietUninstallString 或 shell 解释器，无法安全解析时打开系统应用管理。Linux 通过 `dpkg-query`／`rpm`／`pacman` 共用快照读取已安装软件包，精确匹配实际包名；版本含发行版 epoch／revision 时只展示，不将其当作上游预发布版本比较。确认后再核对身份和版本，在系统终端通过 `pkexec` 运行包管理器的普通移除命令，无自动确认、purge 或 autoremove。AppImage 只允许受管理目录下的普通副本，以 `gio trash` 移到回收站，不永久删除。所有流程保留文件与历史，共用本机刷新；交接不代表完成，Windows／Linux 系统流程须返回或手动刷新核对。iOS 仅提供系统操作指引。

Android 下载、导入、重签及刷新后读取实际 APK 的包名、应用名称、版本名称、长版本码和证书摘要，按原始包／重签包分别保存在 `apkIdentities`。同时按文件保留本次运行中的展示快照，包含实际大小、包名、版本和证书信息，进入文件明细时直接复用；后台读取及自动刷新不清空已显示的内容，失败保留可用快照并提示重试。路径、摘要或已知修改时间变化时不沿用旧文件的展示快照；此快照不写入下载历史，也不替代安装前的独立校验。显示元数据不受安装兼容性检查限制，不兼容当前 ABI 或系统的文件仍可显示身份；安装前继续独立验证。导入包按实际原始包名归组，派生包沿用最初包名；相同显示名称不合并不同包名。只有已知包名与目录应用存在唯一关联时才归入目录条目，不能按文件名猜测。归组不合并文件或签名，仍须逐份选择操作。

“待安装”逐份使用实际目标包名寻找本机身份。未安装的改包副本不会因原版已安装或版本相同而被隐藏；已知证书不同的副本仍待处理。同包名、同证书的文件优先比较实际长版本码，缺失时才比较可解析的版本名称，不把所选 Release 标签当作实际版本码。待安装分类不承诺可覆盖安装，签名冲突、降级及系统确认仍由安装流程处理。本机查询失败保留上次结果并提示重试。

详情网络刷新失败时保留缓存，同时返回 `refreshFailed`；同一会话内再次读取尚未过期的缓存也保留失败标记，成功联网刷新后清除。应用库保留可用详情，显示更新检查失败提示；没有更新条目时显示“更新检查未完成”，不把旧缓存当作本次检查成功。

### 下载续传与 Android 后台执行

每个未完成下载使用同目录的 `.part` 文件和 `.part.json` 侧车记录。记录包含原始 URL、预期 SHA-256、总长度、强 ETag 或有效 Last-Modified；元数据以 `.json.tmp` 原子替换。只有 URL 和预期摘要一致，且具有公开摘要或 HTTP 校验标记时才复用已有字节；取消或网络中断保留可安全续传的内容，没有可靠校验依据的半成品清理后重新下载。

重试发送 Range，有服务器校验标记时同时发送 If-Range。严格检查 206 的范围、总长度和校验标记，服务器返回完整 200 时先截断旧文件，416、范围或标记不一致时放弃旧进度重新请求。完成后仍须核对公开 SHA-256；不一致丢弃半成品。HTML／JSON 冒充安装包、非 HTTPS 最终地址、非 identity 内容编码、超出 4 GB 或长度越界均拒绝；普通资源仍可下载真实文本内容。

网络超时、连接错误、文件传输中断以及 HTTP 408／429／500／502／503／504 最多尝试三次，等待 1 秒、2 秒后重试，取消立即终止等待。重启不会自动下载；用户点击重试后重新核对实际文件长度和侧车记录。删除条目一并清理半成品、侧车及临时侧车，保留其他文件和已安装应用。

Android 用户开始下载后启动非导出的 `dataSync` 前台服务，显示聚合进度通知，可取消下载或返回应用库；服务运行时使用有时限的 CPU 唤醒锁。首次下载时申请通知权限，拒绝通知不授予其他权限或跳过安装确认。普通切换后台时继续已有下载；从最近任务移除应用、系统停止服务、达到后台时限或进程被终止后，需要返回应用显式重试，不承诺强制停止后继续运行。服务不自动重启、不启动新的后台版本扫描，也不安装下载完成的 APK。

自身更新任务沿用下载历史，额外保存 `selfUpdateChannel` 和 `selfUpdateJob`，相同 URL 的不同目标版本不合并。准备安装前和退出前均等待记录持久化，保存失败取消退出。桌面安装进程通过独立任务目录的 `ready`／`cancel`、`result`、`error.txt` 与客户端交接，重启或刷新下载管理时读取结果；没有明确成功结果仍保留未确认状态，不根据版本或文件存在推断安装成功。详见 [客户端自身更新](self-updating.md)。

默认目录名统一为小写 ASCII 的 `downloads`。Windows、macOS、Linux 的新安装和“恢复默认”使用系统下载目录下的该子目录；系统未配置下载目录时沿用应用支持目录下的同名目录。已有目录（包括旧版 `huarunwin` 子目录）与文件保留原位置，不自动迁移。Android 默认使用应用内部存储下的 `downloads`，可选择主外部卷的应用专用文件目录下的同名目录；只提供可直接读写的应用专用位置，不把 SAF content URI 当作普通路径，也不申请全部文件访问权限。外部存储不可用时保留设置与记录，失败可重试，不静默搬迁。iOS 继续使用原有应用目录下的 `downloads`。

下载目录与全部历史受管理根目录一起保存在 `downloadDirectories` 偏好中，兼容读取原 `desktopDownloadDirectories`，新键优先；确认所选目录可写且偏好保存成功后才切换，新任务在创建文件前登记实际规范路径。各任务继续保存自己的绝对文件路径，重试、安装、查看和删除均使用原路径；恢复历史及删除检查允许登记过的原目录，并保留子目录、符号链接与根目录保护。目录选择和新任务目录准备串行执行，切换不改写已创建任务。

Android 从其他应用接收的 APK 仍先进入内部暂存目录；按当前目录复制后先持久化任务，再清理暂存副本，保存失败时保留副本和待确认记录，重复交接不创建第二条任务。原生安装与 FileProvider 仅新增应用专用外部文件目录下的 `downloads` 范围，安装、重签和分享仍逐次核对所选文件，其他外部目录不可作为受管理安装包。目录页的“查看下载文件”返回共用应用库，Android 不向文件管理器暴露整个私有目录。

### 下载链接的已知缺口

网站只把默认平台安装包渲染进初始 HTML。例如 FlClash 页面有 Android APK，没有 Mac DMG。客户端现在会沿网页提供的 GitHub 发布链接，读取对应版本的发布页及附件 HTML，补齐实际存在的 Mac DMG／ZIP／PKG。不会通过替换文件名猜测 Mac 地址，不使用 GitHub JSON API。

GitHub 来源会打开版本与资源选择弹窗。默认优先选有适合当前平台／架构资源的稳定版，Mac 优先当前架构的 DMG、Windows 优先 EXE，Linux 优先发行版包再 AppImage；未知兼容性明确保留。用户可以切换历史或预发布版本，并选择该版本的资源，确认后才下载。App Store 链接使用 `macappstores` 打开系统商店；同时提供商店与 GitHub 安装包时先选择来源。下载完成后由用户点击安装。

设置仅保留“内容来源”的五项统一选择，`ContentSources.githubMode` 派生 GitHub 传输方式：GitHub 镜像为直连、GH-Proxy 为代理、其余为自动回退；选择持久化成功后，`CatalogRepository` 同步配置共用的 `GitHubAcceleration` 并使旧请求结果失效。公开 Raw 文件和应用内 GitHub 附件下载分别保持回退状态 2 小时。GitHub 内容镜像的站内图片跟随最近成功 Raw 线路，单张图片可按当前设置回退，但不改变任何全局保持期；`ContentSourceScope` 同时监听内容来源和内部 GitHub 线路状态，图片按实际传输 URL 分开缓存。内容来源入口与状态行直接显示统一来源名称，代理成功时为 GH-Proxy。原始链接及摘要保留；跨线路续传须有同一预期摘要，否则重新下载。GitHub 版本列表及附件 HTML 暂不经过代理，实际支持范围、超时和手动重试规则见[GitHub 加速](content-sources.md#github-加速)。

版本选择按需读取独立 `/apps/{slug}/releases` 版本页中 `data-client-releases="1"` 的普通链接。网站采集器默认保留当前来源渠道最近 5 个发布，并确保当前推荐版本在内；每个版本携带原始发布页、稳定／预发布标记、发布时间、资料采集日期和真实附件的名称、地址、大小及已有 SHA-256。解析按仓库、标签和文件名核对附件归属，历史数据独立于当前下载入口，不执行脚本、不使用客户端 JSON 内容接口。版本页不提供前台入口、不进入 sitemap，并带有 robots／Googlebot noindex、nofollow 与 HTTP X-Robots-Tag；它是公开资料，不是私有访问控制。初次选择和切换已收录版本复用这些附件，不为缺失摘要再请求 GitHub。

缺少适用的版本资料时沿用公开 Release HTML：历史分页沿真实下一页链接载入，资源按需读取。默认考察首批至多 10 个发布，最新稳定版未在首批出现时读取 GitHub 的公开 latest 页面；不预取全部历史资源。版本资料中“载入更多版本”也只在用户主动操作时访问 GitHub，失败保留已收录版本可选。预发布版明确标注，加载失败支持重试，不静默退到旧版。也可使用网站已提供的下载入口。

每次 GitHub Release HTML 请求另设 30 秒总时限，超时取消该请求；版本与资源的首次选择及切换另设 45 秒总时限，超时、关闭或新选择使旧界面结果失效。失败显示对应的连接、超时或 HTTP 状态提示，版本尚未取得时显示“版本读取失败”。选择弹窗打开期间，底下的下载／更新按钮保持禁用并停止加载动画。Debug 诊断入口及字段见[运行与构建](development.md)。

默认显示所选平台安装包，打开“显示全部资源”可选择其他平台文件、源码和校验文件等；这些资源保留实际链接与公开 SHA-256，普通资源仅下载，不提供安装操作。桌面资源进入下载管理并显示所选版本，旧下载记录继续兼容。同地址重新发布的资源若有新的公开摘要，会重新下载并保留原文件。Android 的 APK 继续进入应用内下载管理，其他资源交给浏览器。

跨平台选择 Windows／Android／Linux 时，仅使用 HTML 中明确标注的平台链接，或读取同一 GitHub 发布页中真实存在的 EXE／MSI／MSIX、APK、DEB／RPM／AppImage 及带平台标记的 ZIP。不会把其他平台安装包代替目标平台文件，也不自动安装异平台应用。选择 iOS 的 App Store 入口时保留原始网页链接，不强制转换为 Mac 商店协议。

非 GitHub 来源、没有 Release 附件或只有不支持格式的应用仍可能需要官方页面或本地导入。2026-10-24 网站与客户端共同增加上述独立版本 HTML 协议；尚未采集或仍使用旧镜像的页面继续沿用原有处理。
